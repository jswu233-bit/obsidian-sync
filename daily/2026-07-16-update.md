### 2) BaoCut 展示了“Agent + Skill + GUI”路线的真实价值

- **来源链接**：[@dotey BaoCut 发布](https://x.com/dotey/status/2077074912435433901)、[@dotey 工作流解释](https://x.com/dotey/status/2077225080027775206)、[@dotey 设计实现循环](https://x.com/dotey/status/2077281462433223043)

### 3) 社区开始讨论高阶模型的“过度设计”和 Token 成本

- **来源链接**：[@gkxspace](https://x.com/gkxspace/status/2077595422642622814)、[@treydtw](https://x.com/treydtw/status/2075763838654574821)、[@Pluvio9yte](https://x.com/Pluvio9yte/status/2077704575130456552)
- **发生了什么**：多位博主反馈 GPT-5.6 Sol Ultra 或高阶推理模式在复杂任务上能力强，但很容易过度设计、耗时长、Token 消耗大。有用户建议把 Ultra 当顾问，而不是日常执行模型；普通任务用 Medium/High 或更快模型组合。
- **为什么重要**：Agent 落地的成本不是 API 单价那么简单，还包括模型自发拆任务、调用子代理、反复调查和上下文膨胀。企业一旦进入规模化使用，这会直接变成预算、延迟和可控性问题。
- **Zoe点评**：**建议把“模型分层使用”写进团队 SOP。** 复杂规划用强模型，明确执行用快模型，验收用另一个高智力模型交叉检查。别让 Ultra 模式承担所有活，它会把简单任务做贵。
